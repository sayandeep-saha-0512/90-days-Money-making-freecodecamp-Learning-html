# AGENTS.md

## Project purpose

This repository is a beginner-friendly HTML learning project. It is not a production app or a framework project. The goal is to practice HTML structure, accessibility, navigation, forms, and simple front-end behavior in a readable way.

Treat this as a teaching and learning workspace. Keep changes understandable for a non-technical learner.

## Project structure

- `index.html`: main learning page and exercises
- `about.html`: personal/about page with links, contact details, and downloadable content
- `style.css`: page styling
- `script.js`: lightweight behavior for smooth navigation and active section highlighting
- `img/`: images used in the exercises
- `README.md`: project overview and learning path

## Working conventions

- Prefer simple, semantic HTML over complicated markup.
- Use clear sectioning elements such as `header`, `main`, `section`, `article`, `nav`, `footer`, and `aside` when useful.
- Keep labels, alt text, and accessibility details meaningful.
- Write comments to explain the purpose of blocks, not to describe obvious code.
- Favor readable code and beginner-friendly naming over clever shortcuts.
- If a task is purely educational, keep the solution easy to understand and explain.

## How to explain commands and code to non-technical people

When helping with this project, describe code in plain language:

- HTML = structure of the page; it tells the browser what the content is.
- CSS = styling; it decides how the page looks.
- JavaScript = behavior; it makes the page react or move.
- Comments = notes for humans; they help explain what a section is for.
- A command or tag is not just a random symbol; it has a purpose and should be explained simply.

If an agent or contributor is asked for help, explain the reason behind a tag or script before the exact syntax.

## Editing guidelines

- Keep the project static and lightweight.
- Avoid adding build tools, frameworks, or package managers unless explicitly requested.
- Do not over-engineer small HTML exercises.
- When modifying pages, preserve the learning intent and readability.
- If adding new content, make it consistent with the beginner education theme.

## Local workflow

This project does not need a build step.

Use one of these approaches:

1. Open the HTML file directly in a browser.
2. Use VS Code Live Server for automatic refresh while editing.

Before finishing a change, verify that the page still renders correctly and that the markup remains accessible and readable.

## Quality bar for future AI assistance

When working here, prefer changes that are:

- easy for a beginner to read
- well-commented where useful
- focused on learning goals
- accessible and semantic
- consistent with the existing simple static-site approach

## Helpful mindset

This project is about learning by doing. The best edits are the ones that help a student understand why something works, not just that it works.
